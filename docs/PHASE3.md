# المرحلة الثالثة — الأنظمة المشتركة والتلعيب (Shared Learning & Gamification)

> هذه المرحلة تقابل «المرحلة الثانية — الأنظمة المشتركة بين جميع الألعاب» في خطة التطوير الشاملة،
> وتأتي بعد مرحلتي جودة الألعاب (PHASE1) وتجربة اللعب والصقل البصري (PHASE2).
>
> الهدف: أن يستخدم المستفيد الألعاب التسع كمنصة واحدة ذات تقدم مترابط، مع بقاء كل لعبة مستقلة في ميكانيكا اللعب.
> كل شيء محلي في المتصفح: لا خادم، ولا حساب، ولا مزامنة.

---

## 1. الملخص التنفيذي

| المحور | ما تحقق |
|---|---|
| XP موحّد | نقاط خبرة واحدة عبر المنصة، منفصلة عن نقاط كل لعبة، تُحتسب من الدقة والإتمام |
| مهارات | ٧ مجالات، دقة تراكمية لكل مجال، ولا تُعرض نسبة إتقان قبل ١٥ سؤالًا |
| شارات | ١٥ شارة مشروطة بالأداء لا بعدد النقرات |
| مراجعة الأخطاء | سجل موحّد لكل الألعاب مع التفسير وإعادة المحاولة والإخفاء |
| مهام يومية | ٣ مهام بتوقيت الجهاز المحلي + مكافأة XP تُستلم مرة واحدة |
| مسارات تعلم | ٤ مسارات مترابطة وتوصية «ما الذي أتعلمه بعد ذلك؟» |
| لوحة تعلّمي | صفحة جديدة `my-learning.html` تعرض كل ما سبق |
| بيانات محلية | تصدير/استيراد JSON مع تحقق، ومسح بتأكيد، وترحيل بيانات المراحل السابقة |

## 3. نموذج البيانات والتخزين

المفتاح: `maktabaplay.progress.v2` — نسخة صريحة `v: 2` تمنع كسر البيانات عند التحديث.

```js
{
  v: 2,
  xp: 0,
  games:  { detective: { plays, total, correct, best, xp, lastAt } },
  skills: { cataloging: { plays, total, correct, best, xp, lastAt } },
  badges: ['first-round', ...],
  flags:  { perfectRound: true },
  mistakes: [{ id, game, key, concept, why, termId, count, at, reviewed }],
  activity: [{ d: '2026-11-28', game, total, correct, xp, at }],   // آخر ٤٠٠ حدث
  missions: { date: '2026-11-28', claimed: ['rounds-1'] }
}
```

- **ترحيل:** عند أول قراءة بلا مفتاح v2 تُقرأ `maktabaplay.best.v1` لتقدير XP والجولات، فلا يفقد المستخدم أفضل نتائجه.
- **سجل المراجعة:** يبقى `maktabaplay.learning.v1` مصدر الأخطاء أثناء اللعب، ويُدمج في v2 عند شاشة النتائج (بمفتاح `game|key` وعدّاد `count`).
- **فشل التخزين:** يُستخدم تخزين مؤقت في الذاكرة مع تحذير واحد في الكونسول، ولا تتعطل اللعبة.
- **الخصوصية:** لا يُرسل أي شيء إلى خادم. التصدير ملف JSON ينزّله المستخدم بنفسه.

## 4. قواعد XP

XP المنصة منفصل عن `score` الخاص بكل لعبة.

| المعيار | القاعدة |
|---|---|
| الوزن الأساسي | الدقة × حجم الجولة: `min(total, 20) × 3 × (accuracy/100)` |
| إتمام الجولة | ‎+10 إن كانت الجولة ٥ أسئلة أو أكثر، و+5 لما دون ذلك |
| مكافأة الإتقان | ‎+10 عند دقة ٩٠٪ أو أكثر في ٨ أسئلة أو أكثر |
| الحد الأقصى للجولة | ٨٠ XP |
| المحاكاة (مهندس المكتبة) | `score / 120` بحد أقصى ٨٠ XP (لا تُقاس بعدد إجابات) |
| سقف التكرار | أول ٣ جولات كاملة لكل لعبة في اليوم، ثم ٥٠٪ |
| السقف اليومي | ٣٠٠ XP في اليوم، والمهمة المعلّقة تُستلم مرة واحدة |
| بدون بيانات | لا تُسجّل جولة بلا XP أو نقاط أو أسئلة |

هذا يمنع تكرار الضغط على «إعادة اللعب» من تضخيم التقدم، ويجعل الدقة أهم من السرعة.

### المستويات

| XP | المستوى |
|---:|---|
| ٠ | مستكشف مبتدئ |
| ١٢٠ | باحث متدرّب |
| ٣٠٠ | فاهر متوسط |
| ٥٥٠ | محقق متمكّن |
| ٩٠٠ | أخصائي مكتبات |
| ١٤٠٠ | خبير معلومات |

## 6. المهام والمسارات

### المهام اليومية

تُبنى من نشاط اليوم (بتوقيت الجهاز المحلي، بلا خادم):

1. إكمال جولة واحدة — ١٥ XP.
2. الإجابة عن ١٠ أسئلة — ٢٥ XP.
3. لعب لعبتين مختلفتين — ٢٠ XP.

تُستلم المكافأة مرة واحدة، وتُصفّر القائمة عند تغيّر التاريخ المحلي.

### المسارات

| المسار | الخطوات |
|---|---|
| الفهرسة | هانج مان → التدريب السريع → محقق MARC21 |
| التصنيف وتنظيم المجموعات | السلم → سباق التصنيف → رتّب الرف |
| خدمات المعلومات | التدريب السريع → موجّه المستفيدين |
| إدارة المكتبات | التدريب السريع → مهندس المكتبة |

تُعرض المسارات في الصفحة الرئيسية وفي لوحة تعلّمي، وتُعلَّم الخطوة المكتملة، وتقترح الواجهة «الخطوة التالية».

## 7. لوحة تعلّمي

`my-learning.html` تعرض:

- بطاقة المستوى: XP، شريط التقدم للمستوى التالي، الشارات، سلسلة الأيام.
- ملخص: الجولات، الأسئلة، الدقة التراكمية، الشارات، المسارات المكتملة.
- توصية «ما الذي أتعلمه بعد ذلك؟».
- المهارات السبع مع دقتها أو سبب عدم كفاية البيانات.
- مهام اليوم مع زر الاستلام.
- المسارات وخطواتها.
- الشارات مكتسبة/مقفلة مع شرح الشرط.
- مراجعة الأخطاء: المفهوم، التفسير، اللعبة، عدد التكرار، رابط إعادة المحاولة، وإخفاء بعد المراجعة.
- بياناتك: تصدير JSON، استيراد مع تحقق وتأكيد، ومسح بتأكيد.

الصفحة تعمل بلا حساب، وتشرح أن التقدم محلي على هذا الجهاز.

## 8. نقاط الربط في الكود

| الموضع | الاستدعاء |
|---|---|
| شاشة نتائج موحّدة | `MPProgress.addMistakes(cfg.id, ML.review.list(cfg.id))` ثم `MPProgress.recordResult({...})` |
| هانج مان (يحفظ عبر `MPStorage`) | جسر تلقائي يلفّ `MPStorage.saveResult` بعد اكتمال تحميل الصفحة |
| مهندس المكتبة | `MPProgress.recordResult({ game:'tycoon', score:G.score, level:G.level })` في `endGame` |
| الهيدر | `MPHeader.setXP(MPProgress.summary().level)` |
| الصفحة الرئيسية | قراءة `MPProgress.summary()` لبطاقات المسارات ولوحة التقدم |

كل استدعاء محاط بـ `try/catch`، فإن غابت الطبقة أو تعطّل التخزين تستمر اللعبة طبيعيًا.

### إضافة لعبة جديدة

1. أضف معرّفها إلى `GAMES` في `game-progress.js` (العنوان، الأيقونة، المهارة، المسار).
2. أضف `skill` المناسب، وأضفها إلى مسار أو أنشئ مسارًا.
3. حمّل `game-progress.js` قبل `game-shell.js`، واستدعِ `MPGame.results` كالمعتاد.
4. إن كانت اللعبة تحفظ عبر `MPStorage` فلن تحتاج استدعاءً إضافيًا.

## 10. القيود المعروفة

- **لا جهاز لمس حقيقي:** التجاوب مختبر بمحاكاة عرض ٣٩٠ بكسل فقط.
- **لا مزامنة:** التقدم مرتبط بالمتصفح/الجهاز، والفقد ممكن عند مسح بيانات المتصفح دون تصدير.
- **لا محتوى مفهومي لكل سؤال:** ربط الأسئلة بـ `conceptId` وأهداف تعلم ومصادر موحّدة لم يُنفّذ بعد (يحتاج مراجعة بنوك الأسئلة).
- **نسبة الذاكرة:** لعبة الذاكرة تُبلّغ دقة ١٠٠٪ عند إتمام الأزواج، فتُحتسب الجولة كاملة؛ سقف XP اليومي يحدّ من أثر ذلك.
- **مهندس المكتبة:** تُقاس الجولة بالنقاط لا بالإجابات، فلا تُضاف إلى دقة المهارة.
- **لوحة الشرف العالمية:** أُبعدت من الواجهة لأنها تتطلب خادمًا آمنًا؛ تُعرض النتائج الشخصية محليًا.
- **الشارات لا تُسحب:** تُحفظ عند اكتسابها ولا تُعاد مراجعتها تلقائيًا عند تغيّر الحالة.
